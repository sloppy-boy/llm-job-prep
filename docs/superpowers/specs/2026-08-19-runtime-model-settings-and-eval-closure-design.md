# 运行时模型设置、余额预警与评测闭环设计

**日期：** 2026-08-19  
**状态：** 已确认，待实施计划

## 目标

在不暴露 API Key 的前提下，让电商售后智能客服可在前端即时切换主模型供应商，并将配置持久化到后端 `.env`；重启后保留已配置的供应商和密钥。新增余额状态和低余额/额度耗尽告警。与此同时，以现有 78 题评测的 9 个真实坏例为回归集，先完成坏例验证，再运行全量评测，真实总准确率达到 **90% 及以上** 后才更新项目数据。

## 已确认的范围

- 预置供应商：DeepSeek 官方、硅基流动。
- 增加一个自定义 OpenAI 兼容供应商，可填写 Base URL、模型名和 API Key。
- 当前主模型可在前端切换；保存后下一条对话立即生效。
- 已保存的各供应商 Key 都保留在 `backend/.env`，切换当前供应商不会覆盖其他供应商 Key，可随时切回。
- 备用模型维持当前配置：硅基流动 `deepseek-ai/DeepSeek-V3`，本次不提供备用模型切换 UI。
- 对可查询余额的供应商展示实时余额和阈值告警；不提供可靠余额接口的供应商明确标示“不支持余额查询”，并在调用返回余额/配额错误时告警。
- 全量 78 题只在坏例回归通过或达到较高通过率后运行；未达标则继续优化坏例，而不是消耗额度反复跑全量。

## 方案选择

采用轻量运行时配置中心：`.env` 是唯一持久化来源，后端负责原子更新和脱敏输出；LLM 调用在每次请求时解析生效的主模型配置。前端不保存 Key，也永远不接收 Key 明文。

未采用浏览器 LocalStorage（会在清缓存/换浏览器后丢失路由配置），也未采用多 Key 历史库、加密存储和完整账单系统（超出当前作品集范围）。

## 配置模型与持久化

### `.env` 字段

保留既有 `DEEPSEEK_API_KEY`、`SILICONFLOW_API_KEY`，新增或规范化以下字段：

```dotenv
LLM_PRIMARY_PROVIDER=siliconflow
MODEL_PRIMARY=deepseek-ai/DeepSeek-V4-Flash

DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
SILICONFLOW_BASE_URL=https://api.siliconflow.cn/v1

CUSTOM_OPENAI_BASE_URL=
CUSTOM_OPENAI_API_KEY=
CUSTOM_OPENAI_MODEL=

BALANCE_WARN_THRESHOLD=5.0
```

`LLM_PRIMARY_PROVIDER` 仅允许 `deepseek`、`siliconflow`、`custom-openai`。每个供应商使用独立的 Key 字段，所以切换路由不会丢失已输入 Key。`.env` 已被 gitignore，任何接口、日志和前端状态均不得返回或打印 Key。

### 后端运行时设置模块

新增独立的设置模块，职责单一：

1. 从环境和 `.env` 解析出完整供应商目录与当前主模型路由；
2. 校验供应商、模型、Base URL（仅接受 `http`/`https`）和非空 Key；
3. 对指定字段执行部分更新；空 Key 代表“保留旧值”；
4. 用临时文件替换方式更新 `.env`，避免半写入文件；
5. 输出脱敏的公共视图，仅含 `hasKey` 布尔值；
6. 更新后清除 LLM 客户端缓存，使下一次请求立即读取新路由。

后端不再在模块导入时固定创建主模型 `OpenAI` 客户端。`chat` 和 `chat_with_tools` 每次调用都通过设置模块取得当前主配置，再从“按配置指纹缓存”的客户端池获取客户端。备用客户端继续使用现有硅基流动 V3 配置和重试逻辑。

## API 设计

所有接口继续受现有 `X-API-Key` 中间件保护。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/settings` | 返回预置/自定义供应商的名称、Base URL、模型、`hasKey`、当前主路由和余额阈值；不返回 Key。 |
| `PUT /api/v1/settings` | 部分更新供应商配置、主路由和余额阈值，写入 `.env` 后立即失效客户端缓存；空 Key 保留已存 Key。 |
| `POST /api/v1/providers/{provider}/test` | 使用已保存的该供应商 Key 进行最小非流式请求，返回成功/失败、模型与 token usage；错误信息截断且剔除 Key。 |
| `GET /api/v1/balance` | 返回当前主供应商余额状态、阈值、查询能力、时间戳和提示文案；不返回任何凭证。 |

`GET /balance` 对 DeepSeek 官方使用 `/user/balance`。硅基流动和自定义 OpenAI 兼容供应商默认 `supported=false`，不虚构金额；若未来有稳定官方余额接口，可通过供应商适配器增加。结果缓存 60 秒，失败不阻断正常对话。

LLM 调用异常会识别 HTTP 402 和余额/配额关键词，记录一个短时“额度异常”状态；前端立即提示并禁用发送。普通网络错误只显示可重试错误，不误判为余额耗尽。

## 前端交互

在工作台标题栏新增：

- **模型设置**按钮，打开设置弹窗；
- **模型状态**标签，展示当前供应商和模型；
- **余额状态**徽标，展示正常、低余额、不可用或“不支持查询”。

设置弹窗包含：

1. DeepSeek、硅基流动、自定义 OpenAI 兼容三张供应商卡片；
2. 每卡的 Base URL、模型名与密码输入框；已配置 Key 只显示“已配置”，留空保存表示不修改；
3. 当前主模型供应商/模型选择器；
4. 余额预警阈值、连接测试和保存按钮。

余额低于阈值显示黄色警告；明确不可用或调用被判定为余额/配额耗尽时显示红色横幅、禁用发送按钮，并引导用户通过设置切换供应商。余额未知和不支持查询均不禁用使用。

## 评测闭环

### 阶段一：坏例回归

从 2026-08-19 的全量结果中固定 9 个失败题构建坏例回归集。优化仅针对可证实的根因，不通过放宽判分来凑分：

- “最新物流节点/当前状态”只要求最新状态，不错误要求完整历史轨迹；
- 区分“请求转人工”和“询问人工客服服务时间/转人工条件”，后两者进入知识库检索；
- 修复七天无理由退货（已使用商品）和数据线长度等检索/上下文命中问题；
- 对“订单商品破损 + 退货运费”等多意图问题，组合订单事实与退换货政策，而不是只返回订单状态；
- 对未知商品和账户安全提示补充可回答依据或明确转人工边界；
- 保持域外问题的确定性拒绝话术和评测要点一致。

每轮只运行坏例回归集。回归集全通过，或达到实施计划定义的高通过阈值且剩余项已有明确、低风险修复方案，才进入阶段二。

### 阶段二：全量验证

在 Qdrant 索引未被后端服务占用、知识库已重新索引的前提下运行完整 78 题。仅当真实结果 `>= 90%` 时：

1. 更新 `CONTEXT.md`、README 和评测记录；
2. 在简历中使用新的准确率和题量。

若全量评测未达到目标，新增失败题回流到坏例回归集，再进入下一轮优化。记录每次实际结果与执行日期；不以模拟输出或未经验证的预估数字替代。

## 错误处理与安全边界

- 配置保存校验失败：返回 400 及字段级错误，保留旧 `.env` 不变；
- `.env` 写入失败：返回 500，不切换内存配置；
- 连接测试失败：返回脱敏错误，不改变当前主路由；
- 自定义端点不可信或协议非法：拒绝保存；
- API Key、Authorization header 和供应商原始错误体不得出现在日志、SSE、测试快照或前端提示中；
- 余额查询失败：返回“无法查询”，不阻塞聊天；仅明确的余额/配额错误才阻止发送。

## 验证

- 后端单元测试：设置持久化/保留 Key/脱敏、供应商校验、客户端切换与缓存失效、余额适配与余额错误分类；
- API 测试：设置读写、连接测试成功/失败、余额四种状态；
- 前端 Vitest：设置弹窗加载/保存/脱敏、状态徽标、低余额与耗尽禁用输入；
- 现有后端与前端全量测试保持通过；
- 评测按“9 个坏例回归 → 78 题全量”门禁执行，最终报告真实分数。
