# 电商售后智能客服 — 待优化清单（Roadmap）

> 用途：把项目的「优化空间 / 与成熟项目差距 / 生产化路径」固化成可勾选的执行清单。
> 优先级：P0 技术硬伤（面试被追问可能露馅）→ P1 功能增强 → P2 质量体系。
> 勾选跟踪：完成一项打 `[x]`。

---

## 一、优化空间

### P0 技术硬伤（建议优先，面试追问风险高）

- [ ] **事件循环阻塞** — 现状：`run_front` 与流式 writer 同步阻塞在 async `gen()` 里，单线程下并发请求互相卡。
      优化：`asyncio.to_thread` 跑前置段；LLM 客户端改异步 / 流式用线程池。价值：并发正确性。工作量：1-2 天。
- [ ] **分块策略粗糙** — 现状：字符级滑动窗口（400/50），可能从表格/句子中间切断。
      优化：按 markdown 结构（标题/段落/表格行）感知分块；或用评测集做分块策略对比实验。
- [ ] **检索加权简化** — 现状：`_keyword_boost` 是字符命中启发式（非标准 BM25）。
      优化：换 `rank_bm25` 做真 BM25 加权；或接 Elasticsearch 做关键词检索。价值：检索精度。
- [ ] **缓存是精确匹配** — 现状：`md5(question)`，语义相近的问题不命中。
      优化：向量相似度语义缓存（embed query → Qdrant 找相似已缓存问题 → 命中）。价值：缓存命中率、成本。
- [ ] **死代码清理** — `agents/state.py` 的 `review_comment`/`iteration`/`review_status` 死字段、`config.py` 的 `max_review_rounds` 死配置（打回循环已移除）。

### P1 功能增强（面试讲深度）

- [ ] **更多售后工具** — 换货 / 催单 / 改地址 / 开发票（现状仅 查单/物流/退款/转人工）。价值：工具广度。
- [ ] **长期记忆 / 用户画像** — 跨会话记住用户（常问什么、历史订单），回答个性化。
- [ ] **多轮澄清** — 订单号不清晰时反问确认，而非直接查错/兜底。
- [ ] **主动式回答** — 检索 + 工具结果综合决策（不只"有工具用工具、有检索用检索"）。

### P2 质量体系

- [ ] **评测集扩充** — 25 题 → 100+ 题，按类目分回归集，badcase 追踪。
- [ ] **对抗测试** — prompt 注入自动化（检索内容/工具结果当数据不当指令）。
- [ ] **人工标注 ground truth** — 校准 LLM-judge，避免自评偏差。

## 二、与成熟项目差距（诚实清单）

| 维度 | 本项目（Demo/作品集级） | 成熟生产系统 |
|------|----------------------|-------------|
| 数据 | mock 订单库（SQLite） | 真实 ERP/订单/物流系统 |
| 鉴权 | 固定 X-API-Key | OAuth/会话 + **订单归属校验**（A 不能查 B 的单） |
| 限流 | 无 | API 限流（令牌桶）/ 按用户配额 / 成本控制 |
| 可观测 | metrics 端点（内存计数） | Prometheus + Grafana / 结构化日志 / trace 链路 / 告警 |
| 安全 | 无注入防护、无 PII 脱敏 | prompt 注入防护 / 脱敏 / 权限隔离 |
| 部署 | 本机 / Docker Compose | 云上多副本 / 负载均衡 / HTTPS / 灰度回滚 |
| DB 治理 | `create_all` 建表 | Alembic 迁移 / 备份 / 连接池 |
| 质量门禁 | 25 题评测 + 66 测试 | 千级评测集 + 自动化回归 + 人工标注 |

> 面试口径：这是**作品集/演示级**，展示能力，不宣称可上线。**要能讲清差距和生产要补什么**——这本身是加分项。

## 三、生产化路径（分阶段）

```
[ ] 阶段 0 数据真实化 —— mock_db → 定义订单/物流/退款「接口契约」，接真实系统
   关键：工具层做成依赖注入，mock 可换真实实现而不改上层
[ ] 阶段 1 安全与鉴权 —— 用户登录 + 订单归属校验；prompt 注入防护；PII 脱敏
[ ] 阶段 2 可靠性 —— 限流（rate limit）；超时/断路器；DB 迁移（Alembic）+ 连接池
[ ] 阶段 3 可观测 —— metrics → Prometheus；结构化 JSON 日志；request-id 链路；告警
[ ] 阶段 4 部署 —— 云服务器 + HTTPS/域名；CI/CD（push→测试→评测→构建→部署）；灰度回滚
[ ] 阶段 5 质量飞轮 —— 评测集扩百级自动跑；badcase 回流修语料/分块/提示词
```

## 四、推荐优先级（1 个月求职窗口）

按「讲起来最值钱 / 工作量」排序，建议做前 4 项：

| 顺序 | 项 | 为什么 | 预计 |
|------|-----|--------|------|
| 1 | 数据真实化 + 鉴权/订单归属校验 | 讲「接口抽象 + 安全意识」，作品集升一级 | 2-3 天 |
| 2 | 限流（README 提过但没做） | 补工程完整度，半天 | 0.5 天 |
| 3 | 可观测完善（Prometheus + 结构化日志） | 讲「生产可观测」，1 天 | 1 天 |
| 4 | 评测集扩充 + CI 自动跑评测 | 把已有 CI 接上质量门禁 | 1 天 |

做完这 4 项，项目从「Demo」→「带生产意识的 Demo」——面试说「我知道生产要什么，已经做了 X/Y/Z」就立住了。
